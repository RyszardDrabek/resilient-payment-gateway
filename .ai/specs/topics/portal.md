# Topic: PORTAL

**Phase:** merchant-and-operator-portal
**Description:** Web application layer providing operator dashboard, merchant webhook self-service, and compliance risk disposition consoles.

## Scope

**In scope.** Responsive Single Page Application (SPA) web portal for operators, risk officers, and merchants:
- Operator KPI overview and unresolved payments investigation console (`F-EDGE-04` integration).
- Merchant self-service webhook endpoint configuration, secret rotation, and test delivery simulator (`F-EDGE-05` integration).
- Compliance console for reviewing AML/fraud risk flags and submitting disposition actions (`F-RISK-01`, `F-RISK-02` integration).
- JWT Bearer role-based access control (`merchant`, `ops`, `risk`).

**Out of scope.** Merchant public customer checkout UI; multi-tenant billing/subscription management; external ticketing system integrations (Jira/ServiceNow); raw database querying from the UI.

## Cross-feature workflows

1. Operator logs in → views KPI aggregate cards → opens Unresolved Payments table → inspects transactions lingering in `Pending`/`Unknown` past SLA (`F-PORTAL-01`).
2. Merchant logs in → manages `MerchantWebhookSubscription` endpoint URL and active state → rotates HMAC-SHA256 secret → triggers simulated test dispatch to verify connectivity and signature validation (`F-PORTAL-02`).
3. Risk officer logs in → reviews open AML risk flags queue → inspects vector anomaly scoring context → submits disposition decision (`Approved`, `Escalated`, `Rejected`) with review notes (`F-PORTAL-03`).

## Glossary

- **Unresolved console** — Interactive table filtering payments lingering in `Pending` or `Unknown` states across channels.
- **Webhook simulator** — Diagnostic UI tool triggering an out-of-band test webhook delivery with real HMAC-SHA256 signature computation and latency measurement.
- **Risk disposition console** — Operational review UI where compliance officers triage anomaly flags generated by the AI risk scoring engine.

## Dependencies

- **EDGE** — `F-PORTAL-01` consumes `F-EDGE-04` query endpoint; `F-PORTAL-02` leverages `F-EDGE-05` webhook models and signing contract.
- **RISK** — `F-PORTAL-03` consumes `F-RISK-01` risk flags and `F-RISK-02` disposition endpoints.
- **PAY** — Core payment domain models and summary representations.

## Decisions taken during /rdf-features

- Structured portal capabilities into 3 distinct user-visible features aligned with the key user roles (`ops`, `merchant`, `risk`).
- Kept UI architecture focused as client-side SPA consuming existing gateway REST APIs with JWT Bearer authentication.
